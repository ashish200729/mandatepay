The API stamps Better Auth's client-IP header from Fastify's socket-derived request.ip, overwriting caller headers. The admin BFF forwards only bounded, allowlisted methods/paths and cookie/origin/content-type/user-agent headers. Behind TLS termination, the configured Origin must match the incoming Host, regardless of Next's reconstructed internal HTTP URL. Forwarded-host headers cannot grant trust.

Limits remain per process, consistent with the MVP. Run one API replica until a shared limiter is added. Requests arriving through the admin BFF share its socket-IP bucket; arbitrary forwarding headers cannot bypass it. Fixture provisioning can raise Better Auth limits only through a programmatic option restricted to NODE_ENV=test and a database ending in _test. Production cannot enable that option through environment or HTTP input. Admin limit/expiry integration tests run with normal limits.

Phase 1 security events use sanitized application logs. Immutable AdminAuditEvent persistence and action/idempotency infrastructure belong to Phase 2. Financial and operational endpoints are absent. Future sensitive handlers must call requireFreshAdminAuth immediately before committing their action and recheck authority under domain transaction locks.

## Configure the chosen account

No development/real account was granted administrator access by this implementation. Synthetic principal fixtures existed only in the isolated test database and were removed afterwards. Selecting the real main account is an operator configuration step.

1. Install locked workspace dependencies and apply migrations with `pnpm --filter @mandatepay/database migrate:deploy`.
2. Configure root/API `ADMIN_ORIGIN=http://localhost:3001`, web `APP_URL=http://localhost:3000`, and admin server `API_URL=http://localhost:4000`. An admin workspace `.env.local` may override the frontend URL keys. Keep database/auth/provider secrets in API/database configuration. Production uses exact HTTPS origins and a configured auth email sender.
3. Use the existing verified Better Auth account chosen by the operator. Admin email verification is mandatory in every environment; configure the normal verification email flow if needed. Bootstrap never marks a user verified or creates a credential.
4. In PowerShell, set `$env:MANDATEPAY_ADMIN_USER_ID` to that actual existing user ID, then run `pnpm --filter @mandatepay/database admin:bootstrap`. Remove the temporary variable with `Remove-Item Env:MANDATEPAY_ADMIN_USER_ID`. Do not include credentials or deployment secrets in the command or commit.
5. Run `pnpm dev:api` and `pnpm dev:admin`, then sign in at the configured admin origin. There is no registration or role-management UI in this phase.

Bootstrap is idempotent for the same verified identity and refuses replacing the main identity or reactivating an inactive record. Account replacement/reactivation requires a separately authorized recovery procedure.
