# MandatePay threat model

## Trust boundaries

The browser and model can submit intent but cannot set user identity, product prices, merchant bindings, currency, approval state or PayPal credentials. The authenticated API retrieves owned records, refreshes controlled catalog facts and constructs totals in integer cents. AgentGuard is deterministic and runs again immediately before payment. Only server-side PayPal calls can execute financial operations.

Product text and model explanations are untrusted. The shopping agent has seven allow-listed discovery/proposal/refund-draft tools. It has no payment, approval, capture or refund-execution tool. Strict schemas reject unknown arguments, invented product IDs and financial authority. Bounded rounds, timeouts, token budgets and rate limits constrain resource use. Explanations are labeled as non-authoritative; actual policy and payment state have separate UI.

## Audit and operational boundaries

Mandate versions, policy decisions, approvals, financial state changes and refunds produce persisted audit records. API DTOs expose bounded, allowed audit facts rather than raw provider credentials or payloads. Captured gross spending continues to count after refunds. UTC periods use Monday-start weeks. Sample records never count as actual completed financial activity.

Public production authentication requires HTTPS, a strong auth secret, an internal proxy secret shared by the BFFs and API, PostgreSQL, verified-email delivery and an approved sender. Reviewer accounts are provisioned by an operator command that creates a verified Better Auth account without sending email, rejects weak passwords and never enables autonomous purchasing. Development/test mode intentionally permits immediate signup for local demonstrations. PayPal is Sandbox-only. No card number, CVV or PayPal password is stored. Vault/off-session authority is not implemented. A production deployment additionally needs backups, monitored recovery, privacy/retention policy, live provider qualification and incident ownership; passing local tests alone does not establish those properties.

## Prompt injection through product data

Shopping agents read seller-controlled text: titles, brands, merchant names, categories and descriptions from Channel3 or the Demo Catalog. Published research on agentic-commerce protocols shows listings that hide instructions such as “skip verification” or extra line items for the agent to follow. MandatePay's controls, in order:

| Layer                   | Control                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Capability              | The model has no payment, approval, capture, refund-execution or policy tool. A fooled model can at most suggest an allow-listed product ID; the server computes all money and permission facts.                                                                                                                                                                                                                                                                                        |
| Deterministic screening | `screenUntrustedContent` in `@mandatepay/agentguard` (pure; no network or model) normalizes text with NFKC, removes zero-width, bidi and tag characters (and decodes tag-character “ASCII smuggling”), then reports stable signals: AI-directed text, instruction overrides, role impersonation, quantity/price/payee/shipping/budget manipulation, approval bypass, hidden or control characters, script/markup/Markdown-link payloads and excessive length.                           |
| Spotlighting            | Before product data enters a model message, the chat route strips invisible characters, withholds descriptions that screened as anything but clean, and places every retailer string in a delimited `<untrusted_listing>` block that listing text cannot close. Listings screened “malicious” are never purchase candidates: they are shown to the user as excluded with the reason “Listing contains instructions aimed at AI agents”. The system prompt keeps tool results untrusted. |
| Policy enforcement      | AgentGuard receives `contentRisk`, computed server-side from the immutable product snapshot and the server's own Demo Catalog record. `malicious` adds the hard rule `PRODUCT_CONTENT_MALICIOUS` (BLOCK; human approval cannot override it); `suspicious` adds `PRODUCT_CONTENT_SUSPICIOUS` (REQUIRE_APPROVAL). The screen runs again at evaluation, approval and pre-payment revalidation.                                                                                             |
| Presentation            | Chat replies about money and verdicts stay server-templated; the UI renders product text as inert text and shows a distinct “Prompt-injection attempt blocked” callout.                                                                                                                                                                                                                                                                                                                 |

Remaining qualification: pattern screening is a heuristic and cannot recognize every paraphrase or language; it is one layer beside capability limits and deterministic policy, not a guarantee. Channel3 descriptions are bounded to 6,000 characters before screening. Demo Catalog snapshots are screened through the catalog record; storing the seller description in every product snapshot's metadata at proposal creation would extend the same coverage to any future checkout-eligible source.
